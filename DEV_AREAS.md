# Trilhas complementares — todas as áreas de desenvolvimento

O dashboard oferece uma trilha geral de engenharia dev. Esta página detalha caminhos opcionais, sempre ligados à qualidade, testes e desenvolvimento seguro.

## Escolha uma área

| Área | Aprender | Referências primárias | Exercício de portfólio |
| --- | --- | --- | --- |
| **Frontend** | HTML, CSS, JS/TS, acessibilidade e componentes | [MDN](https://developer.mozilla.org/pt-BR/docs/Web), [React Learn](https://react.dev/learn) | SPA responsiva acessível com testes |
| **Backend / APIs** | HTTP, autenticação, filas, APIs, padrões e caching | [Node.js Learn](https://nodejs.org/en/learn), [FastAPI](https://fastapi.tiangolo.com/), [Rails Guides](https://guides.rubyonrails.org/) | API local com autorização por usuário e documentação |
| **Banco de dados** | SQL, modelagem, índices, transações e migrations | [PostgreSQL Docs](https://www.postgresql.org/docs/) | Modelo de dados com testes e backup |
| **Mobile Android** | Kotlin, Compose, persistência e arquitetura | [Android Developers](https://developer.android.com/courses) | App local com armazenamento de dados fictícios |
| **Mobile multiplataforma** | Dart, Flutter, estados e UI | [Flutter Learn](https://docs.flutter.dev/learn) | App com formulários, testes e navegação |
| **Mobile Apple** | Swift, SwiftUI e acessibilidade | [Develop in Swift](https://developer.apple.com/tutorials/develop-in-swift) | App de notas fictícias no simulador |
| **Linguagens/algoritmos** | Algoritmos, estruturas, testes, Python, Go | [Python Docs](https://docs.python.org/3/tutorial/), [Go Tutorials](https://go.dev/doc/tutorial/) | CLI que transforma dados sintéticos e gera relatório |
| **Qualidade / QA** | Pirâmide de testes, integração, UI e confiabilidade | [Playwright Docs](https://playwright.dev/docs/intro) | Testes automatizados de aplicação própria |
| **Infra / DevOps** | Docker, CI, deploy, observabilidade, rollback | [Docker Docs](https://docs.docker.com/), [GitHub Actions](https://docs.github.com/en/actions) | Pipeline validado de aplicação fictícia |
| **Cloud / plataforma** | Deploy, IAM, infraestrutura, confiança | [Microsoft Learn](https://learn.microsoft.com/training/), [Kubernetes Docs](https://kubernetes.io/docs/) | Diagrama com least privilege e monitoramento |
| **Segurança no SDLC** | AppSec, threat modeling, SCA, secrets | [OWASP Cheat Sheets](https://cheatsheetseries.owasp.org/) | Modelagem de ameaças e teste de mitigação |
| **Arquitetura / System Design** | Requisitos, escalabilidade, custo, trade-offs | [AWS Well-Architected](https://docs.aws.amazon.com/wellarchitected/latest/framework/welcome.html) | ADR comparando dois desenhos com limitações |
| **Carreira / colaboração** | Comunicação, code review, mentoria e mercado | [GitHub Skills](https://skills.github.com/), [Vídeos de criadores](videos/README.md) | PR revisado e apresentação técnica de projeto |

## Método — teoria → código → revisão → segurança

Para cada área:
1. Estude fundamentos por documentação e faça uma anotação breve em palavras próprias.
2. Execute projeto mínimo com dados artificiais.
3. Acrescente testes unitários, negativos e validação de erros.
4. Revise dependências, secrets e permissões.
5. Registre trade-offs, riscos, limitações, escopo e próximos passos.
6. Peça revisão construtiva à comunidade.

**Atenção:** frameworks mudam. Confira as recomendações nas versões atuais antes de reproduzir tutorial antigo. Não é necessário dominar todas as áreas para ser um bom profissional.
