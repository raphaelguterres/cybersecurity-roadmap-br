# 11 — Engenharia de software e carreira dev

**Objetivo:** construir fundamentos que servem tanto a desenvolvimento profissional quanto a AppSec, DevSecOps e automação defensiva.

Esta trilha é complementar à cibersegurança e não pressupõe que todas as pessoas que trabalham em segurança precisem tornar-se desenvolvedoras full stack.

## Progressão sugerida

| Etapa | Conteúdo | Exercício verificável |
| --- | --- | --- |
| 1 · Lógica | Algoritmos, estruturas de dados, complexidade básica | Escrever solução simples e testes |
| 2 · Ferramentas | Git, terminal, SQL, containers e documentação | Abrir PR pequeno revisável |
| 3 · Frontend | HTML semântico, CSS responsivo, JavaScript, acessibilidade | Página acessível com testes básicos |
| 4 · Backend | HTTP, REST, validação, persistência, authn e authz | API local com testes e controle de acesso |
| 5 · Qualidade | Testes unitários/integrados, CI, logs e observabilidade | Workflow de qualidade e relatório de falha |
| 6 · Arquitetura | Modelagem, trade-offs, custos, caching e confiabilidade | Diagrama e registro de decisão arquitetural (ADR) |
| 7 · Segurança | OWASP, secrets, dependências, revisão e SDLC | Threat model, uma mitigação e reteste |
| 8 · Carreira | Code review, comunicação, entrevistas e colaboração | Portfólio que distingue trabalho comprovado de estudo |

## Projeto final

Crie uma API local de tarefas fictícias com autenticação, autorização por usuário, testes, migrations e documentação de arquitetura. Use dados inventados. Publique análise de riscos e decisões de segurança; nunca credenciais reais.

**Checklist de aprovação:** [ ] funcionalidades testadas · [ ] API documentada · [ ] lógica de autorização validada · [ ] secrets ausentes do Git · [ ] CI reproduzível · [ ] limitações descritas.
